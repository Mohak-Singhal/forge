  3. Architecture on TrueForge

    Forge is Cline with its agent loop replaced by TrueForge (trueforge local mode, npx @truefoundry/trueforge@latest, never deployed). The extension never calls a model provider; TrueForge owns the loop, the model, approvals and streaming.

    Extension ↔ TrueForge. The extension creates a TrueForge session per task and sends turns through the TrueForge TypeScript SDK (client.ts → SdkSessionHost), rendering streamed events in the Cline webview. The agent definition is committed at .trueforge/agents/forge-editor.json: instructions, primary model, preloaded editor tools, and per-tool approval policy.

    Editor capabilities as MCP tools (loopback HTTP server, 127.0.0.1:8791, stateless Streamable-HTTP — fresh server+transport per request; auto-registered with TrueForge at boot as the vscode-editor-tools connector):

    ToolPurposeApproval
    editor_read_fileread file (1-based line range)auto
    editor_searchregex search over workspace → path:lineauto
    editor_repo_mapdef/class signature map of the repoauto
    editor_retrieveBM25 retrieval of code chunks (strategy in §4)auto
    editor_diagnosticsfast Python syntax check (py_compile)auto
    editor_propose_editpropose an exact-hunk edit; after approval applies exactly the hunks the user acceptedper hunk (diff + keep/skip)
    editor_run_commandworkspace shell (destructive/network commands refused)TF-gated
    editor_undo_last_editrestore exact pre-edit bytes of the latest applied proposal (or a named proposalId)TF-gated

    Approval → review flow. TrueForge pauses on tool.approval_required for gated tools. The extension first opens a real vscode.diff tab (original ↔ proposed) via ForgeHunkReview.ts, then asks Keep Hunk / Skip Hunk for each hunk; those decisions are handed to editor_propose_edit through a keyed registry, so a hunk the user skipped is never written even when the harness call was approved. If no review was recorded the tool fails closed: it returns status: "unreviewed" and writes nothing (an explicit headless test seam is the only exception, and the extension never enables it). Forge write tools are also exempted from the AutoApproveBar, so the diff review cannot be skipped by turning on “Use MCP servers”. Applied edits carry their byte pre-image (undoSnapshots), so undo is exact; a stale hunk no longer discards the accepted ones.

    Harness features used, and why. (i) Preloaded tools — deferred discovery made the model call an unmapped read on the first run; preloading fixed it at the harness, not in the model. (ii) Compaction: context_management.compaction with an explicit input_tokens trigger of 120,000, so a long session stays inside the window. TrueForge emits thread.context_compaction_started/finished; the host maps both to visible transcript notes with the actual token count and threshold, rather than running silently. (iii) large_tool_response truncation complements our own retrieval budget. (iv) dynamic_sub_agents, ask_user_questions, iteration_limit 80. (v) Streaming + cancellation ride the SDK cancel path (A3).

  4. How context is selected

    Strategy. The agent never receives whole files up front. Three layers: (1) a repo map of paths plus top-level def/class signatures, itself packed into a 1,500-token budget with omitted-file counts; (2) explicit @mentions — @src/flask/cli.py, @tests/test_cli.py:40-80, @FlaskGroup — parsed and resolved against the workspace by the editor before the model sees anything, then prepended as an un-evictable ground-truth block with line numbers; (3) automatic BM25 retrieval over ~40-line chunks with a skip list for node_modules/.venv/dist.

    The budget is real, not just top-k. Ranking alone is not a strategy: a 17K-line repo yields far more plausible chunks than fit, so context-budget.ts packs the ranked list into a hard token ceiling (default 4,000 tokens, ≤6 chunks, ≤900 tokens per chunk). An oversized chunk is compressed on a line boundary rather than allowed to evict several precise ones. The tool result opens with a report — retrieval budget: N/4000 tokens across K chunks from M candidates — then every drop reason (budget exhausted, chunk cap reached, does not fit…) and, per kept chunk, the matched BM25 terms, score, line range and token cost. That is what makes the selection legible to the agent and to a judge in the session view.

    Why this works on a 17K-line repo. BM25 is lexical (no embedding API, deterministic, no provider dependency); repo-map signatures orient globally; mentions pin ground truth; the budget keeps the rest bounded. In Task B the agent showed the selection live: repo_map → retrieve → search → read_file, then edited three unnamed files (src/flask/cli.py, tests/test_cli.py, docs) without being told their names.

    Rejected alternatives. Whole-file concatenation (window blow-out), embedding RAG (provider dependency — violates "model in TrueForge only"), LSP symbols only (too coarse). BM25 was chosen for determinism and zero external dependency. Unit tests cover budget overflow, compression, ranking, eviction reasons and mention parsing/resolution.

    Approximate cost of the entire rehearsal: $0 (both free). No API key is committed to this repo; the provider key lives only in the TrueForge server's config (see .trueforge/models.example.json for importable provider examples). The extension never sets or reads the provider. To switch models: open TrueForge Settings → Models, add your provider, then change model.name in .trueforge/agents/forge-editor.json (or pick the model in the TrueForge UI/session) and reload — works with any model TrueForge is configured with, any provider.

    Task C / resilience. Failure handling is three-tiered: (1) retry the same model with exponential backoff (400/800/1600/3200 ms, capped) while the error is transient — resets, timeouts, 502/503/504, 429; (2) fail over to the next configured model with no user action by re-pointing the inline session through TrueForge and retrying the same prompt; (3) only when every model is exhausted, emit a message naming all tried models. A bad port or rejected key is deliberately not retried. Verified end-to-end against live TrueForge: primary pointed at 127.0.0.1:9 → [Model Error] Cannot connect to API: bad port → decision next=groq/qwen38-27b → session re-pointed → fallback answered PONG → provider restored. Reproduce with bun run scripts/verify-fallback.mjs. The workspace is untouched because the failure happens before any tool call.

  8. Known limitations & what we'd do with another month

    • Undo granularity. editor_undo_last_edit is byte-exact and LIFO, and refuses if the file changed after the edit. It currently restores a whole proposal rather than a single hunk. Another month: per-hunk undo replay against working tree.
    • Loopback MCP auth. Bound to 127.0.0.1 with TrueForge egress allowlist. Sufficient for single-user local host; multi-user environments would benefit from per-session tokenized auth.
    • Harness snapshots. Upstream Cline checkpoints do not span external agent runs; our undo tool handles file restoration. Another month: bridge TrueForge's snapshot API for full workspace checkpoints.
